# Experiments

Only the lean plan has been run on a GPU (2026-10-06, `data/controlled/LEAN/session.json`). `PLAN.md` (generated) lists every run with its GPU type, hours, cost
and command; `experiments.yaml` is the source of truth.

| File | Role |
|---|---|
| `experiments.yaml` | experiment registry: ids, variants, factors, hours, data folders, minimal subset |
| `PLAN.md` | budget table generated by `make plan` |
| `pricing.yaml` | pod prices with sources, and the dated ECB EUR/USD rate |
| `sla.yaml` | SLOs registered before any controlled run |
| `corpora.yaml` | pinned prompt corpora (sha256 of the assembled text) |
| `workloads/*.yaml` | load definitions: main (E8, E9), subset (factor sweeps), calibration (routing counts, disjoint corpus half), smoke |
| `lib.sh`, `runs/E*.sh` | pod-side runners: boot a variant, sample, drive a workload, stop, collect |
| `tools/` | plan-file and README generators, routing-count converter, PCIe calibration, pinned weight download |
| `pod/` | RunPod creation (dry run unless the budget is approved) and the budget watchdog |

## Result layout

`data/controlled/<exp>/<label>/<run_id>/`:

| File | Content |
|---|---|
| `run.json` | resolved workload, seeds, harness git revision, start/end, status |
| `requests.jsonl` | every request: send time, per-chunk (time, cumulative tokens), first and last token, usage, cached tokens, errors, text head |
| `levels.jsonl` | per (scenario, load point, repetition): seed, wall-clock window, quick summary |
| `server_metrics.jsonl` | full `/metrics` snapshots before and after each level (gauges, counters, server histograms) |
| `samples.jsonl` | sampler: GPU memory, PCIe RX/TX, power, clocks, cgroup and per-process memory, vLLM gauges, largest mappings at start |
| `dmon.txt` | `nvidia-smi dmon` (PCIe cross-check) |
| `serve.log`, `serve_config.txt` | server log and the exact environment and arguments |
| `fingerprint.json`, `nvidia-smi-q.txt`, `nvidia-smi-topo.txt`, `build_provenance.json` | environment and build provenance |
| `status.txt`, `boot.txt`, `failure_signature.json` | boot outcome and, on failure, the classified error line |

## Protocol (summary; the paper's Methodology section is the full version)

- Arrivals: closed loop with staggered starts (no synchronized first wave) and open-loop Poisson streams.
- Phases: prefill probes (unique prompts, 1 output token, one at a time), decode probes (128-token prompts, 512 forced
  tokens, N streams), and mixed scenarios (code 4K, 16K shared prefix, prose 1K).
- Metrics: TTFT, TPOT, per-token latency (chunk deltas divided by tokens per chunk), E2E, windowed aggregate rates,
  p50/p95/p99, server-side queue, prefill and decode histograms.
- Repetitions: 3 per load point inside a boot, plus 3 cold boots at key points; every repetition stored raw;
  cluster bootstrap over repetitions and variance components in the analysis.
- Memory: VRAM per GPU over time, host memory by kind (anon, shmem, file), per-process pinned and locked memory, the
  placement the server logs at load, and the static file-byte split per tensor class.
- PCIe: NVML RX/TX per GPU at 0.5 s, `nvidia-smi dmon`, an nsys capture with GPU metrics, and a calibration of the
  NVML counter against known copy and zero-copy traffic.
